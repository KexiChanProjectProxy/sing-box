## EDGE CASE 1: sing-anytls Replace Directive

### Issue
The replace directive redirects `github.com/anytls/sing-anytls` to `github.com/KexiChanProjectProxy/sing-anytls v0.0.13`.

This is NOT a standard fork dependency - it's a project-specific proxy/fork.

### Current State
- Direct require: `github.com/anytls/sing-anytls v0.0.11` (in both fork and upstream)
- Replace directive: `github.com/anytls/sing-anytls => github.com/KexiChanProjectProxy/sing-anytls v0.0.13`

### Why This Matters
The replace directive means ANY code that imports `github.com/anytls/sing-anytls` will actually
use the KexiChanProjectProxy fork at v0.0.13, NOT the official v0.0.11 release.

This could be intentional (to get patched/modified behavior) or could be a mistake.
The evidence file records this as-is since it was preserved through the merge.

### Verification
```
$ grep -n "anytls" go.mod
7:	github.com/anytls/sing-anytls v0.0.11
195:	replace github.com/anytls/sing-anytls => github.com/KexiChanProjectProxy/sing-anytls v0.0.13
```

## EDGE CASE 2: Tailscale Fork Version With Timestamp

### Issue
`github.com/sagernet/tailscale` uses a pseudo-version format with embedded timestamp.

### Fork (pre-merge) version
```
v1.92.4-sing-box-1.13-mod.6.0.20260303140313-3bcf9a4b9349
```

### Upstream (v1.13.11) version
```
v1.92.4-sing-box-1.13-mod.7
```

### Why The Difference
The `-mod.6.0.20260303140313-3bcf9a4b9349` format suggests a manual fork with a pseudo-version.
The upstream simplified to `-mod.7` which is a release tag format.

### Resolution
Upstream's v1.92.4-sing-box-1.13-mod.7 was adopted (less verbose, proper release tag).
