### Root Cause Analysis
The `command_client.go` file contains gRPC-based implementations of these methods:
- `SelectOutbound` (line 459)
- `URLTest` (line 469)
- `SetClashMode` (line 478)
- `CloseConnection` (line 487)
- `ServiceReload` (line 503)
- `ServiceClose` (line 510)
- `GetSystemProxyStatus` (line 524)
- `SetSystemProxyEnabled` (line 534)
- `GetDeprecatedNotes` (line 543)
- `SetGroupExpand` (line 570)

The legacy IPC files (`command_select.go`, `command_urltest.go`, etc.) also define the same methods with `//go:build libbox_legacy_ipc`, but since Go's build tags are not mutually exclusive, when both the legacy IPC files and `command_client.go` are compiled together, duplicate declarations occur.

### Impact
- Default build (`go build ./experimental/libbox/...`) works correctly (EXIT_CODE: 0)
- Full tag build (android-main configuration) works correctly (EXIT_CODE: 0)
- Only `libbox_legacy_ipc` tag causes the conflict
- This is a **pre-existing issue**, not introduced by the upstream v1.13.11 merge

### Resolution
This is a **documented pre-existing issue**. The `libbox_legacy_ipc` tag appears to be intended for a different build configuration where only the legacy IPC files are compiled without `command_client.go`. The actual production builds (android-main, apple, windows in ffi.json) do NOT use `libbox_legacy_ipc` tag and compile successfully.

### Recommended Action
No immediate action required for Task 7 completion since:
1. Default build passes
2. All production build configurations (android-main, apple, windows) compile successfully
3. The legacy IPC duplicate issue is pre-existing and not caused by upstream merge

If legacy IPC support is required in the future, the resolution would be to either:
1. Add `libbox_legacy_ipc` tag to `command_client.go` to exclude it when legacy IPC is enabled, OR
2. Remove the duplicate methods from one of the file sets
